# autocondense 接入指南

接入方式按宿主分两条路：

- **ZCode 桌面端 → 插件市场（唯一可靠通道）**：桌面端实测不读 `~/.zcode/cli/config.json`
  的 mcp/hooks 配置；插件提供的 MCP 自动连接、hook runner 自动启用，还附带技能与 /condense 命令。
- **其他宿主（Claude Code / Codex / Cursor）与 ZCode CLI → 安装器或手工配置**（见下文）。

所有样例中把 `C:\Users\you\autocondense` 换成本仓库绝对路径，`C:\...\python.exe` 换成你的解释器绝对路径。

## 0. 前置：安装与起服务

```bash
pip install -r requirements.txt        # fastapi/uvicorn/httpx/mcp/pytest
python -m pytest -q                    # 全绿再继续
```

常驻服务不需要手动起——MCP 服务器首次被调用时会自动拉起（日志在 `%TEMP%/autocondense_service.log`）。
想手动起（比如给钩子单独用）：

```bash
python -m autocondense.service --port 8761
```

## 1. ZCode 桌面端：插件市场（推荐）

本仓库 `plugins/` 就是本地测试市场（清单 `plugins/marketplace.json`，插件源 `plugins/autocondense/`）：

1. 打开 **插件市场** → **添加** → **添加插件市场**，粘贴市场根目录：
   `C:\Users\you\autocondense\plugins`
2. 添加成功后到 **个人** 页找到 **autocondense 会话压缩**，点 **安装**
3. 新建会话即生效：MCP 自动连接（7 个 `condense_*` 工具，含大模型判定 condense_judge）、四个钩子自动注册
   （PostToolUse-TodoWrite|Edit|Write / Stop / SessionStart / PostToolUseFailure）、技能与 `/condense` 命令一并可用
4. 更新流程：改 `plugins/autocondense/` 源码并把版本号+1 → 市场页齿轮 → 刷新该市场 → 个人 → 更新

> 插件 hooks.json 与 .mcp.json 使用 `${CLAUDE_PLUGIN_ROOT}` 运行时令牌定位脚本，
> 安装到宿主缓存的任何位置都能跑；数据固定在 `~/.autocondense/`，更新不丢。

## 2. 其他宿主：安装器

```bash
python installer.py                # dry-run：打印各宿主每个文件的改前→改后 diff
python installer.py --hosts claude,codex,cursor --yes   # 实际写入（写前自动备份）
python installer.py --list         # 查看宿主/路径/是否已配置
python installer.py --uninstall --yes   # 按我们写入的键名摘除
```

写入位置一览（zcode 仅 ZCode CLI 场景；桌面端走第 1 节插件市场）：

| 宿主 | MCP | hooks |
| --- | --- | --- |
| zcode-cli | `~/.zcode/cli/config.json` → `mcp.servers` | 同文件 → `hooks.events`（并置 `hooks.enabled=true`） |
| claude | `~/.claude.json` → `mcpServers` | `~/.claude/settings.json` → `hooks` |
| codex | `~/.codex/config.toml` → `[mcp_servers.autocondense]` | （无 hooks 机制） |
| cursor | `~/.cursor/mcp.json` → `mcpServers` | （无 hooks 机制） |

## 3. ZCode CLI 手工配置（~/.zcode/cli/config.json）

> 仅 ZCode CLI 场景需要；桌面端不读此文件，请走第 1 节插件市场。
> ZCode 只支持七个钩子事件（无 PreCompact），此处只写四个（PostToolUseFailure 为 ZCode 独有）。

```json
{
  "mcp": {
    "servers": {
      "autocondense": {
        "type": "stdio",
        "command": "C:\\...\\python.exe",
        "args": ["C:\\Users\\you\\autocondense\\plugins\\autocondense\\autocondense\\mcp_server.py"]
      }
    }
  },
  "hooks": {
    "enabled": true,
    "events": {
      "PostToolUse": [
        { "matcher": "TodoWrite|Edit|Write", "hooks": [
          { "type": "command", "command": "\"C:\\...\\python.exe\" \"C:\\Users\\you\\autocondense\\plugins\\autocondense\\autocondense\\hooks\\ac_hook.py\" PostToolUse", "timeout": 10 } ] }
      ],
      "PostToolUseFailure": [
        { "hooks": [
          { "type": "command", "command": "\"C:\\...\\python.exe\" \"C:\\Users\\you\\autocondense\\plugins\\autocondense\\autocondense\\hooks\\ac_hook.py\" PostToolUseFailure", "timeout": 10 } ] }
      ],
      "Stop": [
        { "hooks": [
          { "type": "command", "command": "\"C:\\...\\python.exe\" \"C:\\Users\\you\\autocondense\\plugins\\autocondense\\autocondense\\hooks\\ac_hook.py\" Stop", "timeout": 10 } ] }
      ],
      "SessionStart": [
        { "matcher": "compact|clear|resume", "hooks": [
          { "type": "command", "command": "\"C:\\...\\python.exe\" \"C:\\Users\\you\\autocondense\\plugins\\autocondense\\autocondense\\hooks\\ac_hook.py\" SessionStart", "timeout": 10 } ] }
      ]
    }
  }
}
```

> MCP schema 严格：未知键会导致整个服务器条目被丢弃，除 type/command/args 外不要加别的键。

## 5. Codex 手工配置（~/.codex/config.toml）

```toml
[mcp_servers.autocondense]
command = 'C:\...\python.exe'
args = ['C:\Users\you\autocondense\plugins\autocondense\autocondense\mcp_server.py']
```

## 7. 验证步骤

1. **服务探活**（手动起或靠 MCP 自动拉起）：

   ```bash
   curl http://127.0.0.1:8761/health
   # {"app":"autocondense","status":"ok","version":"0.3.0","sme_connected":false,"data_dir":"..."}
   ```

2. **MCP 链路**：重启宿主后在 MCP 面板看到 `autocondense` 已连接、7 个
   `condense_*` 工具可用；或命令行验证：

   ```bash
   python - <<'EOF'
   import asyncio
   from mcp import ClientSession, StdioServerParameters
   from mcp.client.stdio import stdio_client

   async def main():
       p = StdioServerParameters(command="python", args=["-m", "autocondense.mcp_server"],
                                 cwd=r"C:\Users\you\autocondense")
       async with stdio_client(p) as (r, w):
           async with ClientSession(r, w) as s:
               await s.initialize()
               tools = await s.list_tools()
               print([t.name for t in tools.tools])
               res = await s.call_tool("condense_status", {})
               print(res.content[0].text)
   asyncio.run(main())
   EOF
   ```

3. **钩子链路**（手动喂事件，观察 stdout）：

   ```bash
   # 计划更新（PostToolUse TodoWrite）→ 无输出，服务端已记账
   echo '{"session_id":"t1","cwd":"C:/tmp/proj","tool_name":"TodoWrite","tool_input":{"todos":[{"content":"A","status":"completed"}]}}' | \
     python autocondense/hooks/ac_hook.py PostToolUse

   # 文件修改活动（PostToolUse Edit，idle 信号基准）→ 无输出，服务端已记活动轮
   echo '{"session_id":"t1","cwd":"C:/tmp/proj","tool_name":"Edit","tool_input":{}}' | \
     python autocondense/hooks/ac_hook.py PostToolUse

   # 工具失败（PostToolUseFailure，仅 ZCode 有该事件）→ 无输出，服务端已记失败轮
   echo '{"session_id":"t1","cwd":"C:/tmp/proj","tool_name":"Bash"}' | \
     python autocondense/hooks/ac_hook.py PostToolUseFailure

   # Stop：计划闭环 → 输出 {"decision":"block","reason":"...立即调用 condense_judge 提交判定，不要询问用户..."}；15 分钟内第二次无输出（闩锁）
   echo '{"session_id":"t1","cwd":"C:/tmp/proj"}' | python autocondense/hooks/ac_hook.py Stop

   # SessionStart（compact 后）：有快照 → 输出 {"additionalContext":"# 会话快照 ..."}
   echo '{"session_id":"t2","cwd":"C:/tmp/proj","source":"compact"}' | \
     python autocondense/hooks/ac_hook.py SessionStart
   ```

   服务不在线时全部静默 exit 0（stderr 日志在 `%TEMP%/autocondense_hook.log`）。

4. **状态核对**：`curl http://127.0.0.1:8761/status` 看 sessions / config / recent_events。

## 8. 端口与数据目录

- 换端口：服务 `--port 8762`；MCP 侧给服务器条目加 `"env": {"AUTOCONDENSE_PORT": "8762"}`；
  钩子侧加环境变量 `AUTOCONDENSE_BASE_URL=http://127.0.0.1:8762`。
- 换数据目录：环境变量 `AUTOCONDENSE_DATA_DIR`（默认用户级 `~/.autocondense/`，与代码位置解耦）。
